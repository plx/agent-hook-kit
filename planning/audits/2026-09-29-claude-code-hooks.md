# Claude Code hook contract refresh

- Audit date: 2026-09-29
- Previous selected snapshot: `docs-2026-08-05-r1` (Claude Code 2.1.222/2.1.223)
- Successor snapshot: `docs-2026-09-29-r1` (Claude Code 2.1.285; npm `stable` 2.1.280)
- Official hook reference: <https://code.claude.com/docs/en/hooks.md>
- Claude Code changelog revision: `2282079d6ac8824ec4b72a432a03e0c636e0512f`
- Corroborating types: `@anthropic-ai/claude-agent-sdk` 0.3.285 (`sdk.d.ts`)

This audit re-read the complete current hook reference and compared every
event section, the exit-code tables, the JSON output rules, and the handler
support lists with the frozen August snapshot. It also reviewed every
hook-related changelog entry from 2.1.223 through 2.1.285, and diffed the Agent
SDK hook input and output types between 0.3.223 (the snapshot-era build) and
0.3.285. The successor is generated by
`cargo run -p xtask --bin generate-claude-contracts`. `WorktreeCreate`,
`snapshot.yaml`, and `sources.yaml` are hand-authored.

## Result

The event inventory grows from 31 to 33. The additions are `PreModelSwitch`, a
blocking event, and `PostModelSwitch`, a context event (both v2.1.251). No
event was removed or renamed.

The larger change is to process semantics that every event shares:

- Claude Code now reads JSON stdout on every exit code.
- Exit 2 still blocks, and the blocking message comes from a JSON `reason`
  when the JSON makes a blocking decision.
- With any other nonzero code, a schema-valid JSON object decides the outcome
  as if the hook had exited 0.
- Since v2.1.248, stdout whose trimmed text starts with `{` and ends with `}`
  is parsed as JSON. A parse failure is a non-blocking error, and on the four
  plain-text-context events the text is dropped.

The successor models these rules as explicit outcomes instead of the August
snapshot's "exit 0 JSON, exit 2 ignores stdout" shape.

Several events now discard universal output fields, and three lose or change a
control channel:

- `Setup` discards every output field.
- `PermissionRequest` no longer honors exit 2.
- `WorktreeRemove` is decided by its exit code alone.

These are behavioral changes for existing HookKit outputs, not only additions.

## Shared process model

Each command binding of an event that follows the standard decision model now
has these outcomes:

| Outcome | Exit | Stdout | Meaning |
| --- | --- | --- | --- |
| `structured` | 0 | schema-valid JSON | the event's control fields take effect |
| `text-context` | 0 | plain text | added as context (SessionStart, UserPromptSubmit, UserPromptExpansion, PostModelSwitch only) |
| `invalid-json` | 0 | brace-delimited text that fails to parse or validate | non-blocking error; context text dropped |
| `exit-2` | 2 | empty, plain, or schema-invalid | event-specific block; stderr is the message |
| `exit-2-structured` | 2 | schema-valid JSON | still blocks; JSON fields are read and a JSON `reason` replaces stderr as the message |
| `nonzero-structured` | 1-255 | schema-valid JSON | treated like `structured`; not reported as an error |
| `nonzero-unstructured` | 1-255 | anything else | usually a non-blocking error with a user notice |

Where an event has an exact `exit-2` outcome, it takes precedence over the
1-255 ranges. Each such contract records that precedence in its uncertainties,
because the metadata language has no "all codes except 2" selector.

Events outside the standard model use a reduced set:

- Output-discarding events (`Setup`, `InstructionsLoaded`, `Notification`,
  `StopFailure`, `PostCompact`, `SessionEnd`) keep `structured` with effect
  `ignored` or `terminal-sequence-only`. They use a single `nonzero` outcome
  where Claude Code shows stderr to the user.
- `WorktreeRemove` has no output schema at all.

HTTP bindings add three outcomes:

- `empty-body`: 2xx with no body is success.
- `non-json-body`: 2xx with a non-JSON body is now a non-blocking error.
- `non-success`: non-2xx. HTTP outcomes now declare stderr as `forbidden`.

The August snapshot described a nonexistent optional stderr channel for HTTP.

Two universal-field semantics changed and are annotated in every output schema:

- `suppressOutput` is accepted but has no effect.
- `stopReason` stays in the conversation, so Claude can see it.

All inputs gain the optional common field `scratchpad_dir` (v2.1.257).
Representative fixtures now include `permission_mode` only for events whose
upstream examples show it. Upstream uses example presence to signal which
events receive the field.

## Classification

Overall, the successor is a breaking protocol refresh:

- Additive: the two model-switch events, `scratchpad_dir`, the SessionStart
  cost fields, `mcp_server`, `classifierContext`, and the new enum values.
- Breaking for existing HookKit outputs:
  - `Setup` context is discarded.
  - `PermissionRequest` exit-2 denial is not honored.
  - `PreCompact` inputs can carry a `null` that a string-typed consumer rejects.
- Behavioral: the rest of the exit-code and discard changes.

The TaskCreated `decision` and the StopFailure enum growth are additive for
HookKit emitters. They are breaking only for consumers that validate real
payloads against the closed August schemas.

Low-confidence points are recorded as uncertainties rather than encoded:

- the Elicitation `decision` sourced only from the changelog;
- MessageDisplay failure notices;
- where the PreCompact auto-compaction message goes;
- internal-agent `agent_id` on SubagentStop;
- the SDK-only `verification_required`.

## Documentation-only and non-command changes

These changes have no command wire field. They are recorded here or in
contract uncertainties:

- `once` now removes a hook only after a successful run.
- Default timeouts are 30 s for `UserPromptSubmit`, `PreModelSwitch`, and
  `PostModelSwitch`, and 10 s for `MessageDisplay`.
- A timed-out PreToolUse command hook does not block.
- `CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS` sets the per-hook default
  (2.1.268).
- `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` controls the Stop continuation cap.
- Hook processes fall back to another working directory when the current one
  is deleted (2.1.239).
- Deduplication now works per handler across settings files.
- The workspace-trust gate holds back settings hooks.
- Skill-frontmatter hooks persist for the rest of the session.
- Matcher tables add canonical model names for the model-switch events, the
  StopFailure additions, and the SessionEnd removal. A FileChanged `"*"`
  matcher watches a literal file named `*`.
- The PreToolUse `permissionDecisionReason` routing changed: `allow` and
  `defer` reasons go to the debug log only.
- The PermissionDenied `reason` format, PostToolUseFailure error-text
  conventions, SubagentStart re-firing, SubagentHandback reports, and the
  task-tool model gating are documented.

Changes to bindings other than `command`, which HookKit does not implement:

- Agent handlers no longer run on PermissionRequest (2.1.280).
- `mcp_tool` hooks are always skipped on Setup, skipped on SessionStart at
  launch, and on blocking events wait for a connecting server (2.1.281).
- HTTP 2xx responses with a non-JSON body are errors.
- Per-event failure contracts apply to HTTP.
- Prompt hooks gain the `impossible` response field.
- Agent hooks lose `continueOnBlock`.
- Async command hooks deliver `systemMessage` and `additionalContext` to
  Claude, not the user, and are not subject to `timeout`.

Environment changes belong to the command-environment supplement, not to this
event snapshot. `CLAUDE_ENV_FILE` is still limited to SessionStart, Setup,
CwdChanged, and FileChanged. The model-switch events need `event_profiles`
entries without `environment-file`.

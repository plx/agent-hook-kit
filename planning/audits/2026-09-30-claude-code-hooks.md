## Shared process model

Each command binding of an event that follows the standard decision model now
has these outcomes:

| Outcome | Exit | Stdout | Meaning |
| --- | --- | --- | --- |
| `structured` | 0 | schema-valid JSON | the event's control fields take effect |
| `no-op` | 0 | empty | no decision to report (new) |
| `text-context` | 0 | plain text | added as context (`SessionStart`, `UserPromptSubmit`, `UserPromptExpansion`, and `PostModelSwitch` only) |
| `plain-text` | 0 | plain text | written to the debug log; no effect (every other event, new) |
| `invalid-json` | 0 | brace-delimited text that fails to parse or validate | non-blocking error (the event's failure effect for `MessageDisplay`) |
| `exit-2` | 2 | empty, plain, or schema-invalid | the event's exit-2 row: a block, a user notice, or a displayed original |
| `exit-2-structured` | 2 | schema-valid JSON | JSON read alongside exit 2 (not for `MessageDisplay` or the elicitation events, which ignore it) |
| `nonzero-structured` | 1-255 | schema-valid JSON | treated like `structured` |
| `nonzero-unstructured` | 1-255 | anything else | the event's failure effect |

The output-discarding events (`Setup`, `InstructionsLoaded`, `Notification`,
`StopFailure`, `PostCompact`, and `SessionEnd`) gain `no-op` and `plain-text`
too. `WorktreeCreate` and `WorktreeRemove` keep their dedicated outcome sets.

HTTP bindings keep `structured`, `empty-body`, `non-json-body`, and
`non-success`. The last two now carry the event's failure effect, and
`non-json-body` is marked `semantic_format: not-a-json-object`.

## Classification

- Relaxing, since the schemas accept more: optional `command_source`; open
  `permission_mode` and `effort.level`; extra `effort` members.
- Additive for emitters:
  - `UserPromptExpansion` `suppressOriginalPrompt`;
  - JSON read with exit 2 on the five notice events.
- Stricter for emitters: `Stop` and `SubagentStop` reject `decision: "block"`
  without `reason`. HookKit's block builders always take a reason.
- Reinterpreted:
  - `MessageDisplay` exit 2 ignores `displayContent`, and its invalid JSON
    displays the original text;
  - HTTP failures follow per-event failure contracts;
  - a `WorktreeRemove` HTTP 2xx with a non-JSON body fails the removal.
- Ledger completeness: the `no-op` and `plain-text` outcomes, and exit-2
  fixtures that really exercise invalid and schema-invalid JSON.

No event, field, or enum value was removed.
